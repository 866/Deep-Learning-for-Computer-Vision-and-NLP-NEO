# BERT Visualization Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add BERT (Devlin et al., 2018) as the third model family in `attention-vis`: a genuinely trained BERT-TINY-sized model whose forward pass runs in JS, drawn with the existing layout builder, with six walkthrough chapters built around the paper's Figures 1–4.

**Architecture:** A new `BertModel.ts` (CPU forward pass + JS WordPiece tokenizer) and `BertModelLayout.ts` (3D block layout) reuse the shared `createLayoutBuilder` encoder block (`createAttention(AttnKind.Self)` = bidirectional, `createLn` post-norm, `createFfn` ReLU) and the existing `matmulWT`/`linearForward`/`layerNormForward`/`attentionForward` helpers. Family selection moves from the growing `kind === 'vit'` branch chain to one dispatch table in `Program.ts`, and six `Bert_*` phases are appended to the walkthrough.

**Tech Stack:** TypeScript, React 18, WebGL2 (existing renderer, unchanged), Vite, esbuild (dev scripts), Python 3.12 + PyTorch + `tokenizers` (training only, in `../.venv`).

**Spec:** `attention-vis/docs/superpowers/specs/2026-10-12-bert-visualization-design.md` — the plan argues from this spec; read both.

## Global Constraints

- No new **runtime** npm dependencies. No new Python dependencies beyond what `../.venv` already has (`torch`, `numpy`, `tokenizers`).
- Node 18+ (repo README). All dev-time JS checks run through the repo's existing esbuild-bundle-then-node pattern, the way `npm run validate` does.
- Weight serialization is fixed: `{'shape': [...], 'dtype': 'torch.float32', 'data': <base64 of float32>}` written by `training/train_vit.py:tensor_to_json`, read by `TensorF32.fromJson`.
- JS must match PyTorch to **worst `max |diff|` < 1e-3**, which is the existing `npm run validate` gate (`scripts/validate-model.ts` exits non-zero above it).
- Model dimensions are fixed by spec §3: `L=2, H=128, A=2, dFF=512, T=32, V=600`, post-LN encoder, Q/K/V/O **with** biases, ReLU FFN, LayerNorm after the embedding sum → **512,348 parameters**.
- Every number quoted in chapter text comes from spec §2. If a real training run disagrees, update spec §2 **first**, then the text.
- BERT-BASE and BERT-LARGE are shapes without weights and must default to `enabled: false`.
- Paper figures are used with attribution: a caption naming the paper on every use, plus `LICENSE-BERT-figures.md`.
- Git: stage **only** paths under `attention-vis/`. Never `git add -A` or `git add .` — the parent repository has unrelated modified files (`notebooks/Module_7_Lecture_13_Transformer.ipynb`) that must not be committed.
- Per-frame budget (spec §8.1): the always-on BERT layout stays **≤ 160 cubes** and layout generation stays **≤ 2 ms**.
- The forward pass never runs inside the render loop; it runs only from `state.bert.pendingSentence` inside `runProgram`.
- Encoder block order (must match the measured checkpoint): self-attention → `ln1` → FFN → `ln2`.

## Review Focus

Failure modes the spec implies but that no single task's happy-path test would catch. Each line gets its test in the named task.

1. **Python↔JS tokenizer drift** — punctuation split off by the PTB-style corpus tokenizer (`it 's`), `##` continuations (`char ##m ##ing`), and truncation must produce byte-identical token ids in JS and Python, or every block in the scene shows values for the wrong token. (Task 3)
2. **Padding keys in bidirectional attention** — a 4-token sentence in a 32-slot sequence must not let pad columns take softmax weight; rows must still sum to 1. The existing `attentionForward` has no padding mask, so the extension must leave causal/self/unmasked behaviour of the other two families bit-identical. (Task 4)
3. **Degenerate input** — empty, whitespace-only, and punctuation-only sentences must produce a full set of finite buffer values and a sentiment probability, never a NaN that renders as a black block or a `Data length does not match` throw. (Task 4)
4. **Over-long input** — a sentence with more than `T-3` subwords must truncate while keeping `[CLS]` and the trailing `[SEP]`, with `truncated: true` surfaced in the UI rather than silently dropping `[SEP]`. (Task 3)
5. **Stale saved state and buffer churn** — a `localStorage` phase from a previous session pointing at a `Bert_*` phase before weights have loaded, and enabling → disabling → re-enabling BERT-LARGE, must not crash or leak block-render buffers. (Task 8)
